WINDOWS 11 x64 · BMW MGU / iDrive 7 · version 0.2.0-beta.3

MGU Assistant

One interface to check the connection, prepare SSH and install MGU Store. Each step is separate: opening the app does not start any vehicle operation.

Independent public beta, not BMW software. Validation consists of local automated tests and one owner-reported F44 success with an earlier private version. Compatibility with all BMW ID7 configurations is not established. Flashing can erase coding/CAFD and Digital Key pairings or leave the HU unusable. The app's checks do not certify every firmware. A correct backup and suitable power supply remain essential. This English release does not expand vehicle support.

Open the application

  1. Extract the entire ZIP to a local folder. Keep MGU-Assistant.exe, _internal and resources together.
  2. For vehicle writes, right-click the EXE and choose Run as administrator. The application does not install services or automatic startup on the PC.
  3. Use DEMO.cmd to explore the interface. Demo data is synthetic, vehicle writes are blocked and no vehicle discovery is performed.
  4. Windows OpenSSH Client is required. Install it through Windows Optional Features if missing. The portable release does not require a separate Python or Node.js installation on the PC.

1 · Connection

Keep the vehicle parked, in P/with the parking brake applied, engine off and ignition on. Connect ENET between the OBD port and the PC Ethernet adapter. Before any write, provide stabilized power suitable for programming the vehicle; do not start with a low battery.

Click Check PC and adapters, select the wired ENET adapter connected to the intended vehicle and click Read HU. Current source accepts link-local 169.254.x.x and private IPv4 addresses (10.x.x.x, 172.16–31.x.x, 192.168.x.x); the published beta.3 ZIP only supports link-local. PC, gateway and HU must share the selected adapter's actual subnet. Discovery uses that subnet's broadcast address; network settings are never changed automatically. Other private-network adapters can appear: do not select Wi-Fi or a VPN. This reads identification and SSH status without flashing or coding. Check the VIN, HWEL/BTLD/SWFL/CAFD identifiers and HU software versions. The BTLD filter 00003F36 does not guarantee compatibility with every firmware. Stop if the VIN is wrong, multiple gateways are found or CAFD is missing.

Independently confirm HU_MGU and iDrive 7. NBT, NBT EVO, iDrive 6, iDrive 8 and iDrive 9 are outside this assistant's supported scope. The vehicle model or year alone is insufficient.

2 · Backup and unlock

Selecting a backup file or folder in the app does not prove it is complete or recoverable. You must have the correct original HU_MGU backup and know how to restore it with BimmerCode or your chosen tool. Keep an independent copy. Have the physical vehicle key available; do not rely only on Digital Key.

The checkboxes confirm checks you have performed yourself. For the first unlock, Flash + Enable… requires explicit confirmation and entry of the VIN. The app uses the original root project procedure for ID7, without bypassing its checks or enabling the advanced unique-key option. It offers no Fix key or automatic reflash as a repair attempt. A local journal blocks further flash attempts for the same VIN even after restarting the application. Do not delete it to bypass the block.

Do not reflash a HU with working SSH root access. During flashing or installation, do not disconnect anything or close the process. There is no cancel button during writes. Read the logs: completion requires root login and persistence with debug disabled, not only a zero exit code.

3 · Key and coding

After a new flash, wait for completion and close all diagnostic connections before using BimmerCode. Restore the HU_MGU backup made before the flash, then check language, menus, audio and original functions. BimmerCode may not restore everything on some vehicles. Resolve any coding problems before installing the Store; do not reflash to fix them.

The assistant does not automate BimmerCode or change the backup. Coding recovery does not restore Digital Key pairings. If SSH was already available and you skipped flashing, confirm that coding and original functions are already working correctly.

The OpenSSH private key is id_rsa, without an extension, not id_rsa.pub or .ppk. You can select an existing key. After a successful unlock, the app selects the exported key path in its local data folder. Do not share its contents. The configured procedure uses the upstream shared bootstrap key, not a key unique to your vehicle.

Use Read HU fingerprint… and carefully accept the HU server fingerprint on the first direct ENET connection. Compare it with an independent trusted reference if available. Without one, this is trust on first use, not independent certification. It is different from the private key fingerprint listed in connect.txt. Changes to a previously accepted host key are rejected. Finally, click Verify root access: this runs only id -u and requires the response 0.

Recover after a completed flash and interrupted enable step

If flashing completed but SSH was not verified, do not repeat Flash + Enable. First restore and verify coding as appropriate for the completed stage. Read the HU again: valid CAFD and an open SSH port are required. On Key and coding, use Recover original key on PC if you did not receive id_rsa. This exports the project's shared bootstrap key locally without modifying the vehicle or overwriting a different key. It cannot recover an unrelated custom key. Then read and confirm the HU fingerprint and click Verify root access.

Only after successful login, backup selection, preparation confirmations and coding checks can you use Complete SSH persistence…. This runs the upstream persistence procedure with the selected key, changes HU services and disables debug. It does not flash, repeat enrollment or restart automatically. Server identity remains checked. If verification fails, keep the log and stop. After success, continue to the Store.

4 · Install Store

The package includes seven verified upstream components: Store 0.9.21, deploy 0.7.17, updater 0.8.25, renderer 0.6.11, HU Python 1.0.2, app-privacy 1.7.1 and uplink 0.7.3. Click Verify package files; hashes are checked again before execution. The local manifest is not a digital signature or a guarantee of safety.

Installation uses these local files without Internet access on the PC to download components. The Include Internet uplink checkbox controls installation of the Internet support component. No GitHub token is needed for the included public files. Installation requires verified root login, correct coding, a backup and stable power. Install MGU Store… changes files and services on the HU; it is not a read-only check.

App-privacy changes application reporting according to its upstream implementation. It does not guarantee invisibility, complete anonymity or warranty coverage.

5 · Restart and verify

Restart HU… is a separate action with confirmation. Use it only after installation succeeds and no writes remain in progress. Wait for iDrive to return, check that the Store opens and verify all original functions fitted to your vehicle. Repeat the checks after the next normal vehicle startup.

Configure supported Wi-Fi/hotspot or tethering inside the Store for Internet access. An online PC does not automatically put the HU online. Install only compatible ID7 apps, one at a time. Store installation alone does not guarantee CarPlay maps or Waze in the instrument cluster.

Local data and troubleshooting

Logs, keys, accepted SSH identities and flash history are stored locally, normally in %LOCALAPPDATA%\MGUAssistant. The assistant does not send telemetry. Logs may contain VINs, addresses and paths; review them before sharing. Confirmation checkboxes are not automatically reused when the app restarts.

Preserve the state folder across updates. Its flash journal only covers attempts recorded on the same PC and in the same state directory, not attempts from older versions, other PCs or different state directories. Deleting state neither undoes HU changes nor proves that another flash is safe.

For compatibility errors, rejected keys, failed persistence, hash mismatches or incomplete coding, stop and keep the log. Do not ignore errors or try unrelated repair tools. The executable is unsigned: investigate security warnings instead of disabling antivirus or Windows protections. A failed overall command can still mean that a vehicle write completed.
